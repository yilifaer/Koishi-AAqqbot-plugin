# 家里测试步骤

照着顺序一步一步做。每一步都写了「应该看到什么」；看到的不一样，就截图反馈给开发者，并附上 Koishi 的日志（Koishi 控制台左侧「日志」页）。

> ⚠️ **红线**
>
> - 插件装在 **Mac mini 上正式的 Koishi** 里（所有者决定，DECISIONS 第 31 条），但测试期间 **AA 网址指向树莓派上的测试 AA**。
> - 测试 AA 的「QQ 群」里**只添加测试群**，**绝不添加任何正式群**。插件只管 AA 上列出来的群，其他群一概不碰。
> - 插件的「运维群号」填**测试运维群**，不能填正式群。
> - 旧的 QQMonitor 插件继续保持**禁用**。
> - 只在**测试群**里测试，只踢**小号**。
> - 密钥自己生成、自己填，**不要发给任何人，也不要贴进任何聊天记录**。截图前把密钥那一栏遮住。

---

## 0. 准备（只需要做一次）

### 0.1 你需要

| 东西 | 说明 |
|---|---|
| 机器人 | 就用 Mac mini 上正式的机器人 |
| 测试群 | 把机器人拉进来并设为**管理员**（群主也可以）。remind / enforce 模式下，机器人也会把群主和其他管理员的名片改成 AA 给的（见 7.2） |
| 测试运维群 | 再建一个小群，只放你和机器人，用来收报告。**不能和测试群是同一个群，也不能是正式群** |
| 1–2 个小号 | 用来测试绑定、验证码、提醒、移出 |
| 树莓派上的测试 AA | 已经装好**新版** aa-qqbot |
| adapter-onebot 的 `responseTimeout` | Koishi 控制台 → 插件配置 → `adapter-onebot`，确认是 `60000`（单位是毫秒；以前被设成过 600，会导致各种「失败」） |

### 0.2 测试 AA 这边

1. 在自己电脑上生成一把测试密钥（打开终端，运行下面这行，把输出记在安全的地方）：

   ```bash
   python3 -c "import secrets; print(secrets.token_urlsafe(48))"
   ```

2. 写进树莓派 AA 的 `local.py`：`QQBOT_API_KEYS = {"koishi-test": "刚才那一串"}`，确认 `APPS_WITH_PUBLIC_VIEWS` 里有 `"qqbot"`，然后重启 AA。
3. 用 QQ 管理员账号登录测试 AA → 侧边栏「QQ 管理」→「QQ 群」→ 添加**测试群**的群号（类型选「固定群」）。**不要把测试运维群加进去。**

### 0.3 Koishi 这边

1. 打开 Mac mini 上的 Koishi 控制台 → 「插件市场」→ 搜索 `aaqqbot` → 添加。
2. 打开 `aaqqbot` 的配置，填：

   | 配置项 | 填什么 |
   |---|---|
   | AA 的网址 | 树莓派的地址，例如 `http://192.168.1.50`（测试时可以用 http，正式环境必须 https） |
   | 密钥编号 | `koishi-test` |
   | 密钥 | 0.2 第 1 步生成的那一串 |
   | 运维群号 | 测试运维群的群号 |
   | 运维名单 | 你自己的 QQ 号 |
   | 宽限期 | 先改成 `1`（1 小时，方便测试） |

   其他保持默认，点「保存」并启用插件。（「防误踢」里的「冷静期」先保持 6 小时，第 7 节测试时再改。）
3. 给自己加权限等级 3：先私聊机器人发一句 `aaqq.status`（会回复「权限不足」），然后在 Koishi 控制台「数据库」→ `user` 表里找到你自己，把 `authority` 改成 `3`。（如果你的权限等级本来就 ≥ 3，这一步跳过。）

## 1. 连通（对应开发阶段 M0）

私聊机器人发送：`aaqq.health`

**应该看到**：`AA 插件版本 1.x.x，配置正常`

看到别的：

| 回复里有 | 怎么办 |
|---|---|
| 登录页 / APPS_WITH_PUBLIC_VIEWS | 树莓派 `local.py` 里缺 `APPS_WITH_PUBLIC_VIEWS += ["qqbot"]` |
| 签名不对 | Koishi 里的密钥和 `local.py` 里的不一致 |
| 时间相差太大 | 树莓派或 Mac 的时间不准，打开自动对时 |
| 无法连接 AA | 网址不对，或者树莓派的 AA 没在运行 |

再发送：`aaqq.status`

**应该看到**：机器人在线、AA 正常、受管群里有你的测试群，模式是 `report（只报告）`。

---

## 2. 只报告的巡检（M1）

私聊机器人发送：`aaqq.patrol`

**应该看到**：

- 私聊回复「已开始巡检」。
- 测试运维群收到一条【AA 巡检】报告：成员人数（不含机器人）、合格 / 不合格人数、不合格的人是谁（按原因分组，一人一行）。
- 如果群主、管理员已经在 AA 绑定、AA 给的名片和现在的不一样：report 模式下只在「本轮动作」里计入「N 人的名片与 AA 不一致（report 模式不修改）」，不改。
- 测试群里**什么都没有发生**（没有人被 @、名片没变）。
- 测试 AA 的「QQ 管理」→「待处理」里，能看到「群里有但没绑定」的 QQ。

---

## 3. 入群申请（M2）

1. 用**小号 A** 登录测试 AA 的一个账号，在「服务」页 QQ 绑定卡片里填小号 A 的 QQ，拿到验证码（例如 `QQ-7K3F9P`）。
2. 小号 A 申请加入测试群，「验证信息」里填这个验证码。

**应该看到**：申请被自动同意；运维群收到「已同意……（验证码验证成功）」；AA 卡片显示「已验证」。

3. 用**没有绑定过的小号 B** 申请加入测试群，验证信息随便写。

**应该看到**：申请**没有**被处理（还挂着）；运维群收到「AA 判定不合格……群模式是 report，留给管理员处理」。你在 QQ 里手动拒绝这个申请。

---

## 4. AA 上的变化（M3）

在测试 AA 上把小号 A 的绑定**解除**。

**应该看到**：1–2 分钟内，运维群收到【AA 变化复查】，小号 A 变成不合格。（report 模式下测试群里仍然什么都不发生。）

然后在 AA 上重新把小号 A 绑定好（这次小号 A 已经在群里，填 QQ 就能直接生效）。

---

## 5. 提醒与名片（M4）

1. 插件配置 → 「群模式」→「单独设置」→ 添加一行：群号填测试群，模式选 `remind` → 保存。
2. 等约 20 秒（保存配置后插件会重启并巡检一次），或者私聊机器人：`aaqq.patrol 测试群号`

   **应该看到**：
   - 运维群报告开头有「ℹ 模式已从 report（只报告）改为 remind（提醒，不踢），本轮开始生效」；
   - 测试群里：已绑定的人名片变成 AA 给的格式（例如 `[IGC] 角色名 - 昵称`）；
   - 没绑定的小号名片前面加上 `【SPY】`；
   - 报告的「本轮动作」里有「同步名片 N 人」「加标记 N 人」。

   如果测试群里没绑定的人比较多（超过阈值：5 人或群人数的 10%，取较小者，至少 1 人），这一轮会先看到「⏸ 冷静期开始」，群里什么都不变；6 小时后的巡检还是这批人，才自动开始加标记。测试群人少，一般 2 个以上没绑定的人就会这样——想马上继续，私聊发 `aaqq.confirm 测试群号`。

3. 测试提醒：把「提醒时间」改成**两三分钟之后**（例如现在 20:07，就填 `20:10`）→ 保存。

   **应该看到**：到时间后，测试群里有一条消息 @ 了没绑定的小号；运维群收到「⏰ 测试群（群号） 已提醒 N 人」。

4. 测试「自己改名片」：用小号把自己的名片前的 `【SPY】` 删掉，然后发 `aaqq.patrol 测试群号`。

   **应该看到**：标记又加回来了。

5. 测试名片长度：在 AA 上给一个已绑定的小号设一个很长的昵称，然后 `aaqq.patrol 测试群号`。如果运维群报告里出现「改名片失败」，请反馈给开发者（需要知道 QQ 名片的实际长度上限）。

---

## 6. 真的移出（M5）

1. 把测试群的模式改成 `enforce` → 保存。约 20 秒后的巡检报告开头有「ℹ 模式已从 remind（提醒，不踢）改为 enforce（提醒并移出）」。
2. 把「提醒时间」改成两三分钟之后 → 保存。到时间后，@ 的消息会带「截止 x月x日 xx:xx」——**截止时间就是从这条提醒开始算的**（刚才宽限期改成了 1 小时）。
3. 等过了截止时间，发送 `aaqq.patrol 测试群号`。（移出前 36 小时内必须成功提醒过这个人，所以一定要先有第 2 步的提醒。）

**应该看到**：

- 没绑定的小号被移出测试群；
- 测试群里有一条「以下成员因未满足本群的要求已被移出……」的公告；
- 运维群报告里写着「已移出 1 人」，下面一行是这个人的名字（名字前面没有【SPY】）。
- 被移出的小号可以重新申请入群（没有被拉黑）。

4. 用没绑定的小号再申请一次入群。

**应该看到**：这次申请被**自动拒绝**，拒绝理由里有绑定网址。

## 7. 安全测试（M6 的一部分）

| 做什么 | 应该看到 |
|---|---|
| 在**测试群**里发 `aaqq.pause` | 机器人**不回应**，插件也没有暂停（发 `aaqq.status` 确认） |
| 私聊发 `aaqq.pause`，再发 `aaqq.patrol` | 暂停后巡检不执行；小号申请入群时不处理；`aaqq.resume` 后恢复 |
| 把树莓派的 AA 关掉，发 `aaqq.patrol` | 运维群报警「AA 连接出问题……不会处置任何人」；测试群里没有任何人被移出或改名片。重新打开 AA 后再巡检，收到「AA 已恢复」 |
| 让另一个 QQ（不在运维名单里）私聊机器人发 `aaqq.status` | 回复「你不在运维名单里」 |
| **冷静期**（前提：测试群模式先改回 `remind`，**不要用 enforce 做这个测试**；测试群里至少有 **2 个已绑定、合格**的普通成员，不是管理员）：在测试 AA 上把测试群改成「身份组小群」，要求的组选一个**没有任何人**的组，然后 `aaqq.patrol 测试群号` | 运维群收到「⏸ 冷静期开始……」；测试群里没有任何人被加标记、@ 或移出。再发一次 `aaqq.patrol 测试群号`：报告开头有「⏸ 冷静中」，群里仍然没变化 |
| 接着上一行：把 AA 上的设置**改回来** | AA 会通知机器人重新巡检，1–2 分钟内（或者你发 `aaqq.patrol 测试群号`）运维群收到「▶ 冷静期结束：……已恢复正常。」，群里没有任何人受影响 |
| （可选）想看「到时间后自动继续」：插件配置里把「冷静期」改成 `1` 小时 → 保存，重复第一行制造冷静期，**不改回 AA**，1 小时后发 `aaqq.patrol 测试群号` | 「▶ 冷静期结束：……情况和 1 小时前一致，开始正常处置」，那 2 个成员被加上【SPY】。测完把 AA 改回来（下一轮会撤掉标记），「冷静期」改回 `6` |

### 7.1 补处理积压的入群申请（需要真机验证）

机器人掉线、AA 掉线、插件暂停期间没人处理的入群申请，插件启动、机器人重新上线、AA 恢复连接、解除暂停时会补处理，规则和实时申请一样：合格的同意，不合格的在 remind / enforce 群里拒绝。这一步在模拟环境里测过，但还没在真的 LLBot 上验证过。测法不用让机器人下线：

1. 找一个**不在测试群里**的小号（例如第 6 节被移出的那个），在测试 AA 上绑定它，拿到验证码。
2. 在 Koishi 控制台把 `aaqqbot` 插件**停用**（只停用插件，不要停机器人）。
3. 小号申请加入测试群，验证信息填验证码。等 1 分钟：申请应该**没人处理**。
4. 把 `aaqqbot` 插件**重新启用**。

**应该看到**：几秒到一分钟内，申请被自动同意；运维群收到「补处理的入群申请：已同意……」。没有的话，截图并附上 Koishi 日志反馈给开发者。

5. （测试群是 remind 或 enforce 时）再用一个**没绑定**的小号重复第 2～4 步。**应该看到**：插件重新启用后，这个申请被**自动拒绝**，运维群收到「🚫 补处理的入群申请：已拒绝……」。
6. 私聊发 `aaqq.pause`，用没绑定的小号申请入群（运维群提示「插件暂停中……恢复后还没人处理的话，会按规则自动补处理」），然后发 `aaqq.resume`。**应该看到**：恢复后这个申请被自动拒绝。

### 7.2 0.2.0 的新功能

| 做什么 | 应该看到 |
|---|---|
| ① 把测试群改成 `report`，连续发两次 `aaqq.patrol 测试群号` | 第一次报告里有「新发现不合格 N 人」；第二次**没有**「新发现」，只有「仍不合格 N 人」。（之前 remind / enforce 时已经记下的人，第一次就直接算「仍不合格」——这是对的，说明插件记住了） |
| ② 管理员名片（测试群是 `remind`，机器人是**管理员**）：让一个群管理员小号在 AA 上绑定好，AA 给的名片和他现在的名片不一样，然后 `aaqq.patrol 测试群号` | 这个管理员的名片被机器人改成 AA 给的；报告里有「同步名片 N 人（其中群主/管理员 N 人）」。万一 QQ 不让改，运维群会列一次「群主/管理员的名片机器人改不了（请自己改成箭头后面的样子）」，再巡检一次**不重复**——出现这种情况请反馈给开发者 |
| ②（顺便看）群主的名片：群主也在 AA 绑定好，AA 给的名片和现在的不一样，再巡检 | 群主的名片也被机器人改成 AA 给的（机器人只是管理员也能改）；QQ 不让改时同样列一次 |
| ③ 每日提醒（第 5 节第 3 步那样改提醒时间） | 提醒发出后，运维群有「⏰ 测试群（群号） 已提醒 N 人」 |
| ④ 把 adapter-onebot 的 `responseTimeout` 临时改成 `600` → 保存 | 机器人重连后，运维群收到「⚠ adapter-onebot 的「responseTimeout」只有 600 毫秒……」。**测完马上改回 `60000` 并保存**（600 时很多操作会失败） |
| ⑤ 不合格的管理员（测试群是 `remind`）：让一个管理员小号在 AA 上解绑，`aaqq.patrol 测试群号`，然后把「提醒时间」改到两三分钟后 | 这个管理员的名片前面加上【SPY】；报告里他后面写着「（管理员，不移出）」；到时间后群里有一条单独的「以下群主/管理员还没有满足本群的要求（不会被移出）……」@ 他，没有截止时间 |

### 7.3 0.2.3 的新功能：离开联盟的人快速处理

AA 判为「没有成员资格」或「账号已停用」的人，机器人一发现就 @ 他，enforce 群里到点直接移出，不等每日提醒和巡检。

1. 测试群模式是 `enforce`；插件配置 →「宽限、提醒与标记」→「离开联盟」的宽限时间改成 `1`（小时，最小就是 1）→ 保存。
2. 小号 A 已经在 AA 上绑定好、在测试群里（合格）。
3. 在测试 AA 的管理后台（网址后面加 `/admin`）→ Users → 找到小号 A 的 AA 账号 → 把「Active」（活动）的勾去掉 → 保存。（这会让 AA 判成「账号已停用」。不会操作的话请 IT 帮忙。）然后私聊机器人发 `aaqq.patrol 测试群号`（停用账号这个操作 AA 不一定会主动通知机器人）。

**应该看到**：

- 测试群里马上有一条 @ 小号 A 的消息：「你在联盟 AA 上已不再具备本群成员资格，将在截止时间被移出本群……」，带截止时间（1 小时后）；
- 小号 A 的名片前面加上【SPY】；
- 运维群有一行「⚡ 测试群（群号） 小号A(QQ) 已不具备成员资格（账号已停用），已提醒，xx:xx 移出」。

4. **什么都不用做**，等过了截止时间 1～2 分钟。

**应该看到**：小号 A 被移出测试群，群里有移出公告，运维群收到「【离开联盟到期处理】……已移出 1 人」。（没有的话，截图并附上 Koishi 日志反馈给开发者。）

5. （可选）撤销测试：把小号 A 的「Active」勾回来，小号 A 重新申请入群（验证信息填验证码），应该被自动同意。
6. （可选）「截止前改回来就不移出」：重复第 3 步，但在截止前把「Active」勾回来，然后发 `aaqq.patrol 测试群号`。**应该看到**：【SPY】被撤掉，到点也不会被移出。
7. 测完把「离开联盟」的宽限时间改回 `2`（或者你们想要的时间）→ 保存。

### 7.4 0.2.4：运维群的报告不再缺段

以前人多的巡检报告有一段每次都收不到（QQ 把一长串「名字(QQ号)」当成广告拒收了）。0.2.4 起名单每条最多 20 行，被拒时自动拆小重发。

1. 升级到 0.2.4 后，私聊机器人发 `aaqq.patrol`（巡检全部群）。
2. **应该看到**：运维群收到的报告每一段都在（序号（1/N）到（N/N）连续，没有缺号）；每条消息里的名单不超过 20 行。
3. 在 Koishi 控制台的日志里搜「被 QQ 拒收」：
   - 没有：说明全部一次发出去了；
   - 有「拆成 N 条重发，全部送达」：被拒过，但已经拆小发出去了（运维群里会看到（3/4-1）（3/4-2）这样的序号）；
   - 有「没有全部送达」或「名字已隐藏」：截图反馈给开发者。

全部通过后，反馈给开发者，一起准备正式上线。

## 8. 测试完，切换到正式 AA

1. 在自己电脑上**重新生成一把正式密钥**（不要沿用测试密钥），交给 IT 写进正式 AA 的 `local.py`，例如 `QQBOT_API_KEYS = {"koishi-1": "新的那一串"}`，并确认 `APPS_WITH_PUBLIC_VIEWS` 里有 `"qqbot"`，然后重启正式 AA。
2. QQ 管理员在正式 AA 前台添加正式的受管群。
