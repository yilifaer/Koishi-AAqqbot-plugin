# 家里测试步骤

照着顺序一步一步做。每一步都写了「应该看到什么」；看到的不一样，就截图发给 Claude，并附上 Koishi 的日志（Koishi 控制台左侧「日志」页）。

> ⚠️ **红线**
>
> - 只在**测试群**里测试，只踢**小号**。
> - 插件只装在**测试用的 Koishi** 里，**不要装进正式机器人的 Koishi**。
> - 密钥自己生成、自己填，**不要发给任何人，也不要贴进和 Claude 的对话**。截图前把密钥那一栏遮住。

---

## 0. 准备（只需要做一次）

### 0.1 你需要

| 东西 | 说明 |
|---|---|
| 测试机器人 QQ | 登录在**测试用的** LLBot 上，连接**测试用的** Koishi |
| 测试群 | 测试机器人是**管理员** |
| 测试运维群 | 再建一个小群，只放你和测试机器人，用来收报告。**不能和测试群是同一个群** |
| 1–2 个小号 | 用来测试绑定、验证码、提醒、移出 |
| 树莓派上的测试 AA | 已经装好**新版** aa-qqbot |

### 0.2 测试 AA 这边

1. 在自己电脑上生成一把测试密钥（打开终端，运行下面这行，把输出记在安全的地方）：

   ```bash
   python3 -c "import secrets; print(secrets.token_urlsafe(48))"
   ```

2. 写进树莓派 AA 的 `local.py`：`QQBOT_API_KEYS = {"koishi-test": "刚才那一串"}`，确认 `APPS_WITH_PUBLIC_VIEWS` 里有 `"qqbot"`，然后重启 AA。
3. 用 QQ 管理员账号登录测试 AA → 侧边栏「QQ 管理」→「QQ 群」→ 添加**测试群**的群号（类型选「固定群」）。**不要把测试运维群加进去。**

### 0.3 测试 Koishi 这边

1. 打开**测试用的** Koishi 控制台 → 「插件市场」→ 搜索 `aaqqbot` → 添加。
2. 打开 `aaqqbot` 的配置，填：

   | 配置项 | 填什么 |
   |---|---|
   | AA 的网址 | 树莓派的地址，例如 `http://192.168.1.50`（测试时可以用 http，正式环境必须 https） |
   | 密钥编号 | `koishi-test` |
   | 密钥 | 0.2 第 1 步生成的那一串 |
   | 运维群号 | 测试运维群的群号 |
   | 运维名单 | 你自己的 QQ 号 |
   | 宽限期 | 先改成 `1`（1 小时，方便测试） |

   其他保持默认，点「保存」并启用插件。
3. 给自己加权限等级 3：先私聊测试机器人发一句 `aaqq.status`（会回复「权限不足」），然后在 Koishi 控制台「数据库」→ `user` 表里找到你自己，把 `authority` 改成 `3`。

## 1. 连通（对应开发阶段 M0）

私聊测试机器人发送：`aaqq.health`

**应该看到**：`AA 插件版本 1.x.x，配置正常`

看到别的：

| 回复里有 | 怎么办 |
|---|---|
| 登录页 / APPS_WITH_PUBLIC_VIEWS | 树莓派 `local.py` 里缺 `APPS_WITH_PUBLIC_VIEWS += ["qqbot"]` |
| 签名不对 | Koishi 里的密钥和 `local.py` 里的不一致 |
| 时间相差太大 | 树莓派或 Mac 的时间不准，打开自动对时 |
| 无法连接 AA | 网址不对，或者树莓派的 AA 没在运行 |

再发送：`aaqq.status`

**应该看到**：机器人在线、AA 正常、受管群里有你的测试群，模式是 `report（只报告）`。

---

## 2. 只报告的巡检（M1）

私聊机器人发送：`aaqq.patrol`

**应该看到**：

- 私聊回复「已开始巡检」。
- 测试运维群收到一条【AA 巡检】报告：成员人数、合格 / 不合格人数、不合格的人是谁。
- 测试群里**什么都没有发生**（没有人被 @、名片没变）。
- 测试 AA 的「QQ 管理」→「待处理」里，能看到「群里有但没绑定」的 QQ。

---

## 3. 入群申请（M2）

1. 用**小号 A** 登录测试 AA 的一个账号，在「服务」页 QQ 绑定卡片里填小号 A 的 QQ，拿到验证码（例如 `QQ-7K3F9P`）。
2. 小号 A 申请加入测试群，「验证信息」里填这个验证码。

**应该看到**：申请被自动同意；运维群收到「已同意……（验证码验证成功）」；AA 卡片显示「已验证」。

3. 用**没有绑定过的小号 B** 申请加入测试群，验证信息随便写。

**应该看到**：申请**没有**被处理（还挂着）；运维群收到「AA 判定不合格……群模式是 report，留给管理员处理」。你在 QQ 里手动拒绝这个申请。

---

## 4. AA 上的变化（M3）

在测试 AA 上把小号 A 的绑定**解除**。

**应该看到**：1–2 分钟内，运维群收到【AA 变化复查】，小号 A 变成不合格。（report 模式下测试群里仍然什么都不发生。）

然后在 AA 上重新把小号 A 绑定好（这次小号 A 已经在群里，填 QQ 就能直接生效）。

---

## 5. 提醒与名片（M4）

1. 插件配置 → 「群模式」→「单独设置」→ 添加一行：群号填测试群，模式选 `remind` → 保存。
2. 私聊机器人：`aaqq.patrol 测试群号`

   **应该看到**：运维群报告里写着「设为了 remind，还没确认，暂时按 report 执行」。

3. 私聊机器人：`aaqq.confirm 测试群号`

   **应该看到**：
   - 回复「已确认……模式升级为 remind……」；
   - 测试群里：已绑定的人名片变成 AA 给的格式（例如 `[IGC] 角色名 - 昵称`）；
   - 没绑定的小号名片前面加上 `【SPY】`；
   - 运维群收到新的巡检报告。

4. 测试提醒：把「提醒时间」改成**两三分钟之后**（例如现在 20:07，就填 `20:10`）→ 保存。

   **应该看到**：到时间后，测试群里有一条消息 @ 了没绑定的小号。

5. 测试「自己改名片」：用小号把自己的名片前的 `【SPY】` 删掉，然后发 `aaqq.patrol 测试群号`。

   **应该看到**：标记又加回来了。

6. 测试名片长度：在 AA 上给一个已绑定的小号设一个很长的昵称，然后 `aaqq.patrol 测试群号`。如果运维群报告里出现「改名片失败」，请告诉 Claude（需要知道 QQ 名片的实际长度上限）。

---

## 6. 真的移出（M5）

1. 把测试群的模式改成 `enforce` → 保存 → `aaqq.patrol 测试群号` → `aaqq.confirm 测试群号`。
2. 第二天的提醒（或者再改一次提醒时间）里，@ 的消息会带「截止 x月x日 xx:xx」。
3. 等宽限期（刚才改成了 1 小时）过去，发送 `aaqq.patrol 测试群号`。

**应该看到**：

- 没绑定的小号被移出测试群；
- 测试群里有一条「以下成员因未满足本群的要求已被移出……」的公告；
- 运维群报告里写着「移出 1 人」。
- 被移出的小号可以重新申请入群（没有被拉黑）。

4. 用没绑定的小号再申请一次入群。

**应该看到**：这次申请被**自动拒绝**，拒绝理由里有绑定网址。

---

## 7. 安全测试（M6 的一部分）

| 做什么 | 应该看到 |
|---|---|
| 在**测试群**里发 `aaqq.pause` | 机器人**不回应**，插件也没有暂停（发 `aaqq.status` 确认） |
| 私聊发 `aaqq.pause`，再发 `aaqq.patrol` | 暂停后巡检不执行；小号申请入群时不处理；`aaqq.resume` 后恢复 |
| 把树莓派的 AA 关掉，发 `aaqq.patrol` | 运维群报警「AA 连接出问题……不会处置任何人」；测试群里没有任何人被移出或改名片。重新打开 AA 后再巡检，收到「AA 已恢复」 |
| 让另一个 QQ（不在运维名单里）私聊机器人发 `aaqq.status` | 回复「你不在运维名单里」 |
| **熔断**（前提：测试群里至少有 **2 个已绑定、合格**的普通成员，不是管理员）：在测试 AA 上把测试群改成「身份组小群」，要求的组选一个**没有任何人**的组，然后 `aaqq.patrol 测试群号` | 运维群收到「⛔ 熔断」；测试群里没有任何人被加标记或移出。测完把 AA 上的设置改回来，再 `aaqq.confirm 测试群号` |

全部通过后，告诉 Claude，一起准备正式上线（先在正式环境用 report 跑一周）。
